# 贡献与发布工作流

## 角色

- GPT-6 Luna high worker 负责全部代码、配置和文档实现。
- 另一位独立 GPT-6 Luna high reviewer 负责验收；不得由实现者自我验收。
- root 负责协调、提交和发布，不承担实现工作。

## 发布前验收

任何源文件上传或服务器测试之前，必须依次通过完整本地测试、生产式打包预检和独立 reviewer 验收。

1. **完整本地测试。** 运行全部 `npm test` 和桌面浏览器验收，覆盖认证与会话、延迟请求和错误状态。默认参与者使用电脑浏览器；移动端适配和移动端验收仅在用户明确提出时纳入范围。迁移 fixture 必须验证旧记录及其 ID、评分、完成状态和账号数据得到保留。使用隔离的临时数据库、测试账号、注册码、监听端口和目录。
2. **生产式打包预检。** 从候选提交生成独立发行包，确认它与待发布提交完全一致，检查文件、依赖和权限。发行包必须带有空的 `data/` 目录（`root:root`、`0755`）；不得包含环境文件、邀请码、可信成员配置或生产数据。以非 root 用户在只读代码目录中启动它；把数据库和测试成员配置放在独立临时目录，并使用单独的 loopback 端口。预检应模拟生产服务的只读文件系统及代理设置，并确认应用只写入测试数据目录。
3. **独立验收。** reviewer 使用同一候选提交和发行包独立重跑必要测试，检查迁移保留、桌面浏览器行为、认证边界和错误处理，并给出明确通过结果。验收后的任何代码或配置修改都必须重跑受影响的测试并重新验收。

上述三项未全部通过，不得上传任何源文件，也不得在生产服务器上做测试。生产 smoke check 只能验证已发布服务状态，不能替代发布前的本地测试、打包预检或独立验收。

规则批量导入也必须先在临时数据库中完成解析、冲突检查、导入和幂等性验证，并由 reviewer 验收候选代码及发行包。工作簿、解析载荷和逐行报告均为私有数据，不进入 Git 或发行包；生产数据导入只能在代码验收发布后、创建新的私有在线备份后作为明确的数据操作执行，不得用生产写入代替测试。

## 通过后的发布

1. 提交并标记已验收的候选版本；只发布与该提交完全匹配的发行包。
2. 使用专用 SSH 配置和已核实的主机密钥。发布前创建 SQLite 在线备份，以及权限受限的应用源代码回滚副本。业务状态位于 `/var/lib/puzarchive`；源代码发布不得复制或覆盖其中的文件。
3. 将发行包传到独立 staging 目录，核对包与候选提交一致，再短暂停止服务、原子切换应用代码并启动一次。不要借此修改环境文件、成员配置、注册码门控、Nginx 或证书设置。
4. 发布后只做只读健康检查和备份校验；在服务器内存中比较旧字段和备份数据，只报告聚合计数与相等性布尔值。不要导出成员 ID、凭据、会话值、注册码、哈希或配置指纹，也不要用注册、审核、投票或评分请求测试生产。
5. 如果服务启动或只读校验失败，停止发布并回滚代码源目录；保留数据库和成员配置原样。修复后从发布前的完整本地测试重新开始。
